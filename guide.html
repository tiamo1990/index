Before You Start

前置准备

解锁 Bootloader 会清空设备全部数据，并可能使官方保修状态发生变化。 动手前请把照片、聊天记录、应用数据完整备份到云端或电脑，并确认电量在 60% 以上。

硬件与环境清单

  • · 一台 Windows 10 / 11 电脑，USB 接口建议直连主板后置
  • · 原装或支持数据传输的 USB 线（劣质线是识别失败主因）
  • · 目标机型为 vivo / iQOO 骁龙 9400 平台（平板不支持）
  • · 已备份全部数据，且清楚各项操作的风险

需要提前下载

  • · vivo USB 驱动 + ADB 便携包（环境类）
  • · 一键解锁工具或临时 Root 包（按路线二选一）
  • · KernelSU / SakiSU 管理器
  • · 计划刷入的内核模块

01

环境部署与设备识别

先安装 vivo 官方 USB 驱动，再解压 ADB 便携包。设备开启「开发者选项 → USB 调试」后连接电脑， 确认 ADB 能正确列出设备。这一步不通，后面全部无法进行。

adb version adb devices # 输出应包含一行形如 3A21FDH200XXXX device 的记录 # 若显示 unauthorized，请在手机屏幕点击「允许 USB 调试」
vivo_usb_driver.exe ADB 便携包
02

路线选择：临时 Root 还是永久解锁

这是整个流程中最重要的决策点。两条路线并不互斥——可以先走临时路线验证需求，再决定是否永久解锁。

免解锁 临时 Root

不写分区、不改动 Bootloader 状态，重启后权限自动消失。 代价是无法长期驻留，内核模块与部分需要开机自启的功能受限。

需解锁 永久解锁 + KernelSU

一次性解锁 Bootloader 并写入 KernelSU，获得持久、完整的 Root 能力， 可自由刷入内核模块与主题破解。代价是清空数据。

仅尝鲜 → 临时 Root 长期使用 → 永久解锁
03

解锁 Bootloader（永久路线）

解压「vivo / iQOO 9400 一键解锁工具」压缩包，保持 test.exe 与主程序同目录， 以管理员身份运行并按提示操作。工具会自动完成设备检测、解锁申请与分区写入。

解锁过程中设备会多次重启并自动清空数据，这属于正常现象，全程请勿拔线。 解锁完成后首次开机会出现「设备已解锁」提示。
一键解锁工具 会清空数据 不支持平板
04

刷入 Root 管理器

解锁完成后，安装 KernelSU 管理器接管 Root 权限。若使用 SakiSU 方案， 则安装对应的 SakiSU APK，两者择一即可，不建议同时启用。

adb install KernelSU_v3.2.5-44-g0f65ab64.apk # 打开 App 确认「已安装」且版本号与内核匹配
KernelSU 管理器 SakiSU（替代方案）
05

刷入内核模块

在 KernelSU 管理器的「模块」页面逐项选择 zip 文件安装并重启生效。 建议按下面的顺序推进，先装依赖、再做功能增强，出问题时更容易定位。

1
基础依赖层

Zygisk Next → magic_mount_rs。这两项是后续模块运行的前置条件。

2
系统稳定性层

block_vivo_ota / 屏蔽系统更新 → AutoADB WiFi → RescueX 救援模块。

3
性能调度层

GPU Governor / 线程调度 / ExtremeGT / 极致性能。 同类模块不要叠加，选中一个即可。

4
外观与隐藏层

MiSans 字体模块（四选一）→ FontLoader → 月虹隐藏 / 移除温控。

不要一次性刷入全部模块。 每装 2–3 个就重启验证一次，确认开机正常后再继续，否则很难判断是哪个模块导致的启动异常。
Zygisk Next magic_mount_rs MiSans 字体 性能调度 Root 隐藏
06

主题与系统 UI 替换

这一阶段依赖 LSPosed 环境：先确认 Zygisk Next 已就绪并启用 LSPosed， 再安装主题破解模块，最后替换 SystemUI 资源。

a 安装并启用 LSPosed 框架，确认作用域勾选系统 UI 与主题商店
b 刷入对应系统版本的「主题破解」模块（15.5.0.1 以上请选新版）
c 用 MT 管理器替换 SystemUI 资源，或直接导入 .itz 主题包
d 重启并校验：状态栏、通知面板、快捷开关是否全部生效
主题破解 v114514 15.5.0.1+ 破解 仿小米主题包 SystemUI 资源 MT 管理器
Troubleshooting

异常处理速查

按顺序排查：① 更换 USB 线与接口（优先主板后置口）；② 重新安装 vivo USB 驱动； ③ 设备端把 USB 模式从「仅充电」改为「传输文件」；④ 在设备管理器中查看是否有带感叹号的未知设备， 如有则手动指定驱动目录；⑤ 关闭电脑上的手机助手类软件后重试。
这是设备尚未授权调试。点亮手机屏幕查看是否有「允许 USB 调试」弹窗并勾选「始终允许」。 若没有弹窗，进入开发者选项执行「撤销 USB 调试授权」后重新插拔；仍无效可尝试重启 ADB 服务： adb kill-server → adb start-server。
这是典型的「有 root 无实权」。使用资源库中的修复临时 root 无实权脚本， 在 ADB Shell 中推入并执行，即可恢复挂载与写入权限。执行后建议用 id 命令确认 uid=0。
长按电源键强制重启，多数情况下 KernelSU 会在检测到连续启动失败后自动进入安全模式并禁用全部模块。 若未自动进入，可在开机时按音量键组合触发安全模式，进入后逐个禁用最近安装的模块定位问题。 这也是为什么不要一次性刷入多个模块的原因。
刷入 block_vivo_ota 或 vivo 屏蔽系统更新 模块阻断升级流程。 切勿在解锁状态下直接接受 OTA，覆盖安装极可能导致 Root 环境失效甚至无法开机。
